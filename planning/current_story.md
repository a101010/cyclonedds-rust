# Current story: topic-field-metadata

This file is the detailed, living plan for the one active story. It is rewritten for each
story. The backlog in `backlog.md` holds all work and the per-story status.

## Story

Emit an `impl cyclonedds::DdsFieldMetadata` for every type generated by `cyclonedds-build`, using
`DynamicTypeSchema`/`DynamicValue` for the schema and conversions. Add field get/set defaults to
the trait. Resolve typedefs to their underlying type in codegen, and set schema bounds/flags from
the IDL AST rather than losing them in the Rust type mapping.

- **Depends on:** none.
- **Minimal test:** `cyclonedds-test-suite/tests/field_metadata.rs` enumerates a generated topic's
  fields from `field_schema()` and round-trips a value through `to_dynamic_value()` and
  `from_dynamic_value()`.

## Context

The to-stations tool `dds-echo` (and the future `tentacles-injector`) needs to build generic field
views for any topic registered in `contracts/topics.toml`: a detail pane for captured samples and a
send form for new samples. Rust has no runtime reflection, so the field knowledge has to be
generated at compile time.

The fork already generates every Rust type from the shared IDL, and `cyclonedds` already owns a
runtime schema/value model:

- `DynamicTypeSchema` (`cyclonedds/src/dynamic_value.rs`): struct/enum/union/bitmask/sequence/
  array/string/primitive shapes, including `optional`, `key`, `bound`, and union labels.
- `DynamicValue` (`cyclonedds/src/dynamic_value.rs`): the corresponding value tree.
- `DynamicValue::field`, `set_field`, and `validate_against`: field access and validation.

What is missing is the bridge from a generated typed struct to those shapes. Building the schema
at runtime from the descriptor/ops is lossy and incomplete (`type_discovery.rs` keeps only
`field_0`, `field_1`, ... and placeholder element types), so it cannot be used for a field UI.

## Decisions

1. **Implement in `cyclonedds-build` codegen, not `cyclonedds-derive`.** The IDL AST already has
   field names, scopes, annotations, bounds, typedefs, enum literals, union labels, and bitmask
   flags. Emitting conversion code from the AST handles all of those without teaching the derive
   about `DdsString`/`DdsSequence` shapes a second time. Hand-written `#[derive(DdsType)]` types
   are out of scope; the same trait can be implemented for them later if needed.
2. **One opt-in trait, not new `DdsType` methods.** `DdsFieldMetadata` is separate so manual
   `DdsType` impls and `no_std` builds are unaffected. It is `native`-gated because
   `DynamicTypeSchema`/`DynamicValue`, `DdsString`, and `DdsSequence` are native-gated. Generated
   files already require `native` (they import `DdsSequence`/`DdsString` unconditionally).
3. **Reuse `DynamicTypeSchema`/`DynamicValue` unchanged.** Do not add a second metadata model.
   `field_schema()` returns `&'static DynamicTypeSchema` cached in a generated `OnceLock`;
   conversions produce/consume `DynamicValue`.
4. **Schema is built from the IDL AST.** Preserve `string<N>` bounds, sequence bounds, array
   dimensions, `@optional`, `@key`, and the qualified schema name (same string as
   `#[dds_typename]`). `member_id` is the declaration index (the auto ID the derive emits today);
   `extensibility` is `Final`; `external`/`must_understand`/`hash_id_name` are left at their
   defaults.
5. **Typedefs are inlined, not impl'd.** A Rust `pub type` is transparent; `impl` on an alias would
   be an impl on the underlying type. Codegen follows the typedef chain (cycle-guarded) and emits
   the underlying type's schema/conversion. A typedef to a generated struct/enum/union/bitmask can
   still use the underlying trait impl because the alias is the same type.
6. **Field get/set are trait defaults.** They convert the whole sample to `DynamicValue`, call
   `DynamicValue::set_field` (which validates against the field schema), and convert back. This is
   O(fields) per operation but simple, correct, and enough for a GUI; tools that need many reads
   can call `to_dynamic_value()` once.
7. **Emit metadata unconditionally.** No new `CompileOptions` field or CLI flag. The metadata is
   additive and the fork is the source of truth for to-stations. A field type that does not
   implement `DdsFieldMetadata` (for example a type generated elsewhere) fails at compile time with
   a clear missing-trait error rather than producing an empty schema.
8. **No new dependencies and no new `unsafe`.** The generated code uses `std::sync::OnceLock`,
   `std::collections::BTreeMap`, and the existing safe `DdsString`/`DdsSequence` constructors.
   The unsafe inventory does not change.

## Interfaces

### `cyclonedds/src/field_metadata.rs` (new)

```rust
pub trait DdsFieldMetadata: Sized + 'static {
    fn field_schema() -> &'static DynamicTypeSchema;

    fn to_dynamic_value(&self) -> DynamicValue;

    fn from_dynamic_value(value: &DynamicValue) -> DdsResult<Self>;

    fn field_names() -> Vec<String>;
    fn get_field(&self, name: &str) -> DdsResult<DynamicValue>;
    fn set_field(&mut self, name: &str, value: DynamicValue) -> DdsResult<()>;
}
```

Default behavior:

- `field_names()`: for a `DynamicTypeSchema::Struct`, the field names in declaration order;
  otherwise an empty vector.
- `get_field()`: `self.to_dynamic_value().field(name).cloned()`, or
  `DdsError::BadParameter` with the missing field name.
- `set_field()`: `to_dynamic_value`, `DynamicValue::set_field(Self::field_schema(), ...)`, then
  `from_dynamic_value`. This makes `set_field` reject type-mismatched values through the existing
  schema validation.

`lib.rs`: add `#[cfg(feature = "native")] mod field_metadata;` and
`pub use field_metadata::DdsFieldMetadata;`.

### Generated impl shape

For a struct `Foo` in module scope `dds::hello_world`:

```rust
impl cyclonedds::DdsFieldMetadata for Foo {
    fn field_schema() -> &'static cyclonedds::DynamicTypeSchema {
        static SCHEMA: ::std::sync::OnceLock<cyclonedds::DynamicTypeSchema> =
            ::std::sync::OnceLock::new();
        SCHEMA.get_or_init(|| cyclonedds::DynamicTypeSchema::Struct {
            name: "dds::hello_world::Foo".to_string(),
            base: None,
            fields: vec![
                cyclonedds::DynamicFieldSchema {
                    name: "greeting".to_string(),
                    member_id: 0,
                    value: cyclonedds::DynamicTypeSchema::String { bound: None },
                    optional: false,
                    key: false,
                    external: false,
                    must_understand: false,
                    hash_id_name: None,
                },
                // ...
            ],
            extensibility: Some(cyclonedds::DynamicTypeExtensibility::Final),
            autoid: None,
            nested: false,
        })
    }

    fn to_dynamic_value(&self) -> cyclonedds::DynamicValue {
        let mut fields = ::std::collections::BTreeMap::new();
        fields.insert("greeting".to_string(), cyclonedds::DynamicValue::String(self.greeting.clone()));
        // ...
        cyclonedds::DynamicValue::Struct(fields)
    }

    fn from_dynamic_value(
        value: &cyclonedds::DynamicValue,
    ) -> cyclonedds::DdsResult<Self> {
        let fields = value.as_struct().ok_or_else(|| {
            cyclonedds::DdsError::BadParameter("expected struct value for dds::hello_world::Foo".into())
        })?;
        Ok(Self {
            greeting: {
                let field = fields.get("greeting").ok_or_else(|| {
                    cyclonedds::DdsError::BadParameter("missing field 'greeting'".into())
                })?;
                match field {
                    cyclonedds::DynamicValue::String(value) => value.clone(),
                    other => return Err(cyclonedds::DdsError::BadParameter(
                        ::std::format!("field 'greeting': expected String, got {other:?}")
                    )),
                }
            },
            // ...
        })
    }
}
```

Nested generated types call their own impl:

```rust
<super::math::Quaternion as cyclonedds::DdsFieldMetadata>::field_schema().clone()
<super::math::Quaternion as cyclonedds::DdsFieldMetadata>::to_dynamic_value(&self.attitude)
<super::math::Quaternion as cyclonedds::DdsFieldMetadata>::from_dynamic_value(value)?
```

## Codegen changes

### `SymbolTable` / typedef resolution

Extend the private `SymbolTable` with:

```rust
struct TypedefInfo {
    scope: Vec<String>,        // module scope where the typedef was declared
    target: IdlTypeRef,        // underlying type
}

typedefs: HashMap<String, TypedefInfo>  // fully-qualified IDL typedef name
```

Add a resolver used by the metadata emitters:

- `lookup_typedef(ref_name, scope)` applies the same absolute/relative candidate rules as
  `resolve_named`.
- Follow chains while the target is another named typedef, with a visited set. On a cycle, emit a
  `compile_error!`-style message (codegen already runs after parsing; the simplest safe behavior is
  to fall back to a trait call and let the compiler report it).
- Return the final non-typedef `IdlTypeRef` and the scope it was written in.

When a named reference resolves to a typedef:

- final target is a primitive/string/sequence/array: inline `schema_expr`, `to_expr`, `from_expr`
  using the final target and its defining scope;
- final target is a named generated type: keep the original alias Rust path and emit a trait call
  (`<Alias as DdsFieldMetadata>`); the impl on the underlying type applies because the alias is
  transparent;
- named reference that is not a typedef: emit `<RustPath as DdsFieldMetadata>`.

Typedefs get no `impl` block of their own.

### Emission

Add codegen helpers that return Rust source snippets:

- `schema_expr(ty: &IdlTypeRef, scope, symbols) -> String`
- `to_expr(ty: &IdlTypeRef, value: &str, scope, symbols) -> String`
- `from_expr(ty: &IdlTypeRef, value: &str, scope, symbols) -> String` (an expression of type
  `DdsResult<T>`, so callers can `?` it)
- `field_metadata_impl_struct`, `..._enum`, `..._union`, `..._bitmask`

`generate_type` appends the relevant impl after the type definition. The impl block is part of the
returned string, so the existing `indent` in `generate_module` applies normally.

Struct emission:

- schema: one `DynamicFieldSchema` per field, in declaration order;
- `to_dynamic_value`: insert every field, using the field conversion expression;
- `from_dynamic_value`: require a `DynamicValue::Struct`, read each field by name, return
  `BadParameter` on a missing required field or a wrong variant;
- optional fields: `None`/`DynamicValue::Null` map to `None`; `Some` maps to the inner conversion;
  a missing optional field in the input is `None`.

Enum emission:

- schema: `Enum { name: "<fq>", literals: [name/value...], bit_bound: None }`;
- `to_dynamic_value`: `DynamicValue::Enum { value: *self as i32 }`;
- `from_dynamic_value`: match the `i32` back to the variant; unknown value is `BadParameter`.

Bitmask emission:

- schema: `Bitmask { name, fields: [{name, position}], bit_bound: Some(N) }` with positions in
  declaration order (the derive's bit assignment);
- `to_dynamic_value`: `DynamicValue::Bitmask(self.to_bits())`;
- `from_dynamic_value`: `DynamicValue::Bitmask(bits)` -> `Self::from_bits(*bits)`.

Union emission:

- schema: `Union { name, discriminator: schema(disc_type), cases: [...], autoid: None,
  nested: false }`; each case includes its IDL name, `member_id` (declaration index), value schema,
  all case labels, and the `default` flag;
- `to_dynamic_value`: match the Rust variant; `DynamicValue::Union { discriminator, field, value }`
  uses the case's first label, or a deterministic discriminator not present in any label for the
  default case;
- `from_dynamic_value`: match on `field` (the IDL case name); non-default cases check the
  discriminator against their labels; the default case accepts any discriminator.

### Type mapping

| IDL | Rust generated type | Schema | DynamicValue |
|---|---|---|---|
| `boolean` | `bool` | `Primitive(Boolean)` | `Bool` |
| `octet` | `u8` | `Primitive(UInt8)` | `UInt8` |
| `char` | `u8` | `Primitive(Char8)` | `Char8` |
| `wchar` | `u16` | `Primitive(Char16)` | `Char16` |
| `short`/`unsigned short` | `i16`/`u16` | `Primitive(Int16/UInt16)` | `Int16`/`UInt16` |
| `long`/`unsigned long` | `i32`/`u32` | `Primitive(Int32/UInt32)` | `Int32`/`UInt32` |
| `long long`/`unsigned long long` | `i64`/`u64` | `Primitive(Int64/UInt64)` | `Int64`/`UInt64` |
| `float`/`double` | `f32`/`f64` | `Primitive(Float32/Float64)` | `Float32`/`Float64` |
| `long double` | `f64` | `Primitive(Float64)` | `Float64` |
| `string` | `String` | `String { bound: None }` | `String` |
| `string<N>` | `DdsString` | `String { bound: Some(N) }` | `String` (`to_string_lossy` / `DdsString::new`) |
| `sequence<T>` | `DdsSequence<T>` | `Sequence { bound: None, element }` | `Sequence` |
| `sequence<T, N>` | `DdsBoundedSequence<T, N>` | `Sequence { bound: Some(N), element }` | `Sequence` |
| `T[N]` | `[T; N]` | `Array { bounds: [N], element }` | `Array` |
| named generated type | generated path | `<Path>::field_schema()` | `<Path>` conversion |
| `@optional T` | `Option<T>` | inner schema, `optional: true` | `Null` / inner |
| typedef | underlying Rust type | inline underlying schema | inline conversion |

Sequence conversion uses `iter()` -> collect `DdsResult<Vec<_>>` -> `DdsSequence::from_vec` (or
`DdsBoundedSequence::from_vec`). Array conversion collects to `Vec<_>` then `try_into` to
`[T; N]`, returning `BadParameter` on the wrong length. String conversions handle `String` (clone)
and `DdsString` (`to_string_lossy` / `DdsString::new(s)?`) separately.

## Known limitations (explicitly out of scope)

- Generated structs still cannot contain enum, bitmask, or union fields: codegen derives
  `Default`/`PartialEq` on structs, those generated types lack the needed impls, and enum fields
  lack `#[dds_enum]` in codegen. Metadata impls are emitted for those types standalone so the
  metadata layer is ready when the field support is fixed.
- `wstring` is still mapped to `String`; its schema is treated as `String` (the existing codegen
  already loses the distinction).
- Hand-written types using `#[derive(DdsType)]` do not get metadata. Only `cyclonedds-build`
  output does.
- No conversion to/from `DynamicData` or CDR; this story only bridges typed samples and
  `DynamicValue`.

## Implementation order

1. Add `cyclonedds/src/field_metadata.rs`, the module/re-export, and doc comments.
2. Add `TypedefInfo` + resolver to `cyclonedds-build`'s `SymbolTable`.
3. Add `schema_expr`/`to_expr`/`from_expr` and the four impl emitters; wire them into
   `generate_type`.
4. Add codegen unit tests for emitted markers and typedef inlining.
5. Add the test-suite fixture and round-trip test.
6. Update `CHANGELOG.md` and `cyclonedds-build/README.md`.
7. Run the verification commands below.

## Tests

### `cyclonedds-build` unit tests

- a generated struct contains `impl cyclonedds::DdsFieldMetadata for ...`;
- an `@optional` field emits `optional: true` with the inner schema;
- a typedef field inlines the underlying primitive instead of calling a trait on the alias;
- enum, bitmask, and union definitions each get their impls.

### `cyclonedds-test-suite/tests/field_metadata.rs`

1. Enumerate `<field_meta::MetadataTopic as DdsFieldMetadata>::field_schema()`; assert field
   names/order, primitive kinds, `String` bounds, sequence bounds, array bounds, `optional` flags,
   and that `Inner`/typedef fields have the expected schema.
2. Build a sample, call `to_dynamic_value()`, then `from_dynamic_value()`; assert the typed sample
   is unchanged.
3. `get_field`/`set_field` by name for a scalar, a nested struct, and an optional field
   (`None` ↔ `DynamicValue::Null`, `Some` ↔ inner); assert the typed value changes.
4. Round-trip `Color`, `Flags`, and `Choice` through their own metadata.
5. A wrong-variant `set_field` and a missing required field return `BadParameter`.

## Follow-up in `to-stations-proto` (after the fork commit is available)

The to-stations `topic-field-metadata` story consumes the fork and says "re-pin the fork rev."
Once the fork commit is pushed:

1. update the pinned rev in `rust/Cargo.toml` and `scripts/build.ps1` (`$forkRev`);
2. update `rust/Cargo.lock` (`cargo update` for the fork packages);
3. regenerate `build/gen/rust/hello_world.rs` and confirm the new impls appear;
4. update `planning/cyclonedds-build-plan.md`, `docs/versions.md`, and `README.md` with the new
   rev/feature;
5. run `.\scripts\build.ps1 -Test` and `.\scripts\build.ps1`.

No `dds-echo` UI changes here; that is the next story, `dds-echo-send`.

## Risks / open checks

- **Codegen expression complexity.** Recursive `schema_expr`/`to_expr`/`from_expr` must agree on
  every shape. Mitigate with the test-suite round-trip covering each supported field kind, plus the
  codegen unit tests.
- **Typedef cycles.** Illegal in IDL, but the resolver must not recurse forever; the visited set
  plus a compile-time failure is the guard.
- **`OnceLock` schemas.** Nested schema construction clones child schemas at first use. No
  recursive IDL types exist, so there is no initialization cycle.
- **Existing struct-field limitation.** If a future IDL adds enum/bitmask/union fields, the struct
  still fails for the pre-existing derive/codegen reasons above; this story does not make that
  worse but does not fix it either.
- **Trait visibility.** `DdsFieldMetadata` is exported only with the `native` feature; a consumer
  that generates code but builds `cyclonedds` without `native` already fails on the generated
  `DdsSequence`/`DdsString` imports.
